# Pairwise independence of AES-like block ciphers in Lean

This is a Lean 4 formalization of the main results of the paper *Pairwise independence of AES-like block ciphers* from EUROCRYPT 2026.
It also formalizes the result of Keliher and Sui about the maximum probabilities of differentials in four AES rounds, on which these results rely.
With the exception of this README, every file in this repository has been generated by an LLM.
In general, I do not recommend reading the Lean code in this repository, except for the theorem statements and the definitions they depend on.


## Theorem statements and definitions

This is the only code that you need to read to verify correctness, assuming there are no issues in Lean and mathlib.
The theorem statements are in the top-level files `Theorem3.lean`, `Theorem4.lean`, `Theorem5.lean`, `Corollary2.lean` and `KeliherSui.lean`.
Each file states one result as a proposition (for example `def Theorem5 : Prop := …`).
This is relatively short (around 40 lines of Lean code), but these statements depend on the following definitions:

- [`Pairwise/Definitions.lean`](PairwiseIndependence/Pairwise/Definitions.lean)
  (48 lines of code): difference-distribution matrices, pairwise independence,
  the SHARK construction and the MDS property.
- [`AES/AES.lean`](PairwiseIndependence/AES/AES.lean) (64 lines of code): AES definition following FIPS 197.

The proofs are separate theorems, such as `theorem theorem5_aesFourRounds : Theorem5`, listed in the mapping below.
Building the project checks them, and the root file `PairwiseIndependence.lean` prints the axioms each one uses.

  and `AES/SboxFieldCertificate.lean` validate that implementation against
  FIPS 197. The main results do not use them.

## Building

The project is pinned to Lean `v4.23.0-rc2` (`lean-toolchain`) and a fixed
mathlib commit (`lakefile.toml`, `lake-manifest.json`). With
[elan](https://github.com/leanprover/elan) installed:

```bash
lake exe cache get
lake build
```

To avoid large memory usage, consider restricting the number of threads:

```bash
LEAN_NUM_THREADS=1 lake build
```

With one thread, peak memory usage is about 6.3 GB.
